# SUMI TRADE LAB

Ethereumウォレットを読み取り、DEXの価格・流動性と5分足を照合して、5分間隔のBUY／SELL判断を紙上で生成する実験用ダッシュボードです。

## 現在できること

- GeckoTerminalから720本の5分足を取得

- 注文額とDEX流動性からAMM価格影響を推定し、動的スリッページへ反映

## v1.1 ポートフォリオリスク判定

v1.1では、個別銘柄がチャート・契約・流動性・コスト判定を通過しても、ポートフォリオ全体が次の上限に達した場合は新規BUYをHOLDへ変換します。コミュニティトレンドの紙上ローテーションも同時に停止します。

| 判定 | 上限・条件 | 動作 |
| --- | --- | --- |
| 単一資産集中 | 全資産の35%超 | 新規BUY停止 |
| 高相関ペア | 相関0.85以上かつ合計配分50%超 | 新規BUY停止 |
| ETH連動集中 | ETH相関0.85以上かつ対象配分25%以上 | 新規BUY停止 |
| 24時間損失 | 3%以上 | 新規BUY停止 |
| 連敗 | 3連敗以上 | 新規BUY停止 |
| 相関・記録不足 | 計算不能または保存未設定 | Fail Closedで新規BUY停止 |

相関は価格水準ではなく単純リターンから算出し、最低12リターン（13価格）を必要とします。外部API停止や保存未設定を安全とみなさず、判定不能時は `DATA WAIT` として新規BUYを止めます。すべての停止はBUY側だけに適用し、SELLは出口として維持します。

## v1.2 OSS戦略比較基盤

v1.2では、SUMIの局面判定に加えて、EMA 9/21順張りとRSI 30/70平均回帰を比較対象にしました。すべての戦略へ同じ確定済み5分足、次足始値約定、片道ガス代、スリッページ、損切り・利確ルールを適用し、条件差による見かけの優位性を抑えます。

ランキングはローリングOOS収益を優先し、同率時は最大ドローダウン、戦略IDの順で決定します。結果は `RESEARCH ONLY` であり、首位戦略への自動切替、実注文、署名、承認、calldata生成には接続しません。

設計上は、Freqtradeの未来参照検査、vectorbtの共通データ上での戦略比較、Jesseのベンチマーク比較という考え方を参考にしています。各OSSのソースコードを取り込むのではなく、SUMI固有のTypeScript実装として再構成しています。

## 現在できないこと

このバージョンはオンチェーン署名・トークン承認・スワップ送信を実装していません。画面上の注文はすべてペーパートレードです。秘密鍵やリカバリーフレーズを環境変数へ保存しないでください。

v1.3のオンチェーン状態プリフライトは `eth_chainId`、`eth_getBlockByNumber`、`eth_getCode` だけを使用します。スワップ取引の生成、`eth_call`、`eth_estimateGas`、署名、送信は行いません。

## v1.3 オンチェーン状態プリフライト

許可トークンごとにEthereum mainnetへの接続、最新ブロックの時刻、コントラクトコードの存在を同一RPCバッチで確認します。最新ブロックが3分を超えて遅延している、chainIdが1ではない、コードが空、RPCが未設定・不完全な場合は新規BUYをHOLDへ変換します。判定が停止しても既存資産のSELLは出口として維持します。

## v1.4 パフォーマンスダッシュボード

昇格条件は従来どおり直近7日・最低30件のまま固定し、分析用の記録保持だけを30日に拡張します。24時間・7日・30日の成績を並べ、コスト控除後の累積損益カーブ、銘柄別損益、平均勝ち、平均負け、ペイオフ比を表示します。

30日分析はチャートモデルの診断材料であり、昇格条件や売買モデルを自動変更しません。既存データは過去のTTLで削除済みの場合があるため、リリース直後の30日欄は保存済み期間分だけを集計します。

## v1.5 リスク判定の時刻整合性

資産間相関とETH相関は、各系列の末尾を機械的に揃えず、timestampが一致する確定済み5分足だけをinner joinして単純リターンを計算します。最低12リターンを確保できない銘柄は相関を推測せず、`DATA WAIT` として新規BUYを停止します。画面には最大ETH相関の整合サンプル数と、全相関比較で最も少ないサンプル数を表示します。

連敗判定は7日間の過去最大連敗と、最新結果から続く現在連敗を分離しました。新規BUYを止めるのは現在3連敗以上の場合だけです。最大連敗はモデル品質の分析指標として残し、最新の勝ちで現在連敗は0へ戻ります。SELL経路と実行ハードロックは変更しません。

## v1.6 運用安全制御

`SUMI_EMERGENCY_STOP=true` は最優先の環境停止です。通常時はUpstash Redisの永続停止状態を確認し、停止中・取得不能・不正状態のすべてで新規BUYをHOLDへ変換します。停止中も市場観測、紙上採点、既存資産のSELL候補は維持します。

紙上シグナルには5分バケット・モデル・対象・方向から決定論的な `decisionId` を付け、同じ判断が再取得されても重複採点しません。また、最新の確定5分足が15分を超えて古い場合は、過去バックテストを表示用に残しながら現在判断をHOLDへ固定します。

永続停止APIは `SAFETY_CONTROL_SECRET` のBearer認証で保護されます。16文字未満または未設定ならAPI自体を503で閉鎖します。値はソース、ログ、チャットへ保存しません。

```powershell
$headers = @{ Authorization = "Bearer $env:SAFETY_CONTROL_SECRET" }
$body = @{ enabled = $true; reason = "手動安全停止" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "https://sumi-trade-lab.vercel.app/api/safety/emergency-stop" -Headers $headers -ContentType "application/json" -Body $body
```

解除時は `enabled = $false` とし、理由に解除根拠を記録します。環境変数側が `true` の間はRedisを解除しても停止が優先されます。

## v1.7 紙上運用準備度

30件の採点だけが短期間に揃ってもモデルを合格扱いにしません。最初の保存済みスキャンから168時間以上、直近24時間の5分スキャン網羅率80%以上、最新スキャンが12分以内という3つの運用品質条件を追加しました。モデル成績を含む全条件が揃うまで `COLLECTING` または `BLOCKED` を維持します。

ダッシュボードには観測時間・24時間網羅率・最新記録の鮮度・総合運用ゲートを表示します。`/api/health` でも同じ状態を確認できますが、ウォレットアドレス、Redis接続情報、Bearer secretは返しません。条件通過後も `PAPER MODE` と `executionLocked: true` は解除されず、実売買へ自動移行しません。

## v1.8 本番設定監査

`/api/health` は、本番運用に必要なウォレット、Cron secret、Redis、ダッシュボード認証、緊急停止secret、Ethereum RPC、緊急停止値の妥当性をBooleanと不足キー名だけで返します。環境変数の値はレスポンスへ含めません。

Cron・ダッシュボード・安全制御のsecretは16文字以上を合格条件とし、RedisはUpstash名またはVercel KV互換名のURL・トークン組を確認します。全項目が揃わない場合は `configurationStatus: blocked` とし、`PAPER MODE` と実行ハードロックを維持します。

GitHub Actionsはmain更新後と毎時17分に本番healthを確認します。デプロイ直後はv1.8が反映されるまで最大5分待機し、設定不足、安全制御取得不能、紙上エンジン停止、PAPER MODEまたは実行ロックの逸脱を失敗として通知対象にします。

## v1.9 本番監視履歴と復旧通知

本番healthの監視結果を、秘密値を含まないJSON監査レポートとしてGitHub Actionsへ30日間保存します。異常検知時は `production-health` ラベル付きIssueを自動作成し、継続中は同じIssueへ追記します。正常復旧を確認すると復旧コメントを残してIssueを自動クローズします。

## v1.10 紙上取引CSVエクスポート

認証済みダッシュボードから、直近30日以内に6時間後採点まで完了した紙上取引をCSVでダウンロードできます。チャートモデルとコミュニティトレンドを含み、判断ID、方向、想定価格、コスト、コスト後損益、勝敗、実行ロック状態を記録します。CSV数式インジェクションを防止し、ウォレットアドレスや環境変数の値は含めません。

## v1.11 モデル劣化監視

7日間の紙上成績を30日基準と比較し、平均コスト後リターンとProfit Factorの急落を検出します。7日10件・30日30件に達するまでは収集状態とし、少数サンプルによる誤停止を避けます。

十分な証拠と7日損益のマイナスが揃った場合だけ新規BUYを停止します。SELLは常に維持します。成績データを取得できない場合はFail Closedとし、PAPER MODEと`executionLocked: true`を維持します。

## v1.12 モデル別サーキットブレーカー

チャートモデルとコミュニティトレンドの24時間・7日・30日成績を別々に集計します。各モデルを同じサンプル数・平均リターン・Profit Factor基準で評価し、劣化したモデル側の新規BUYだけを停止します。

チャートモデルが悪化してもコミュニティトレンドの紙上ローテーションは継続でき、コミュニティトレンドだけが悪化した場合もチャートモデルのBUY候補は維持します。ポートフォリオリスク・緊急停止・データ取得不能などの全体安全ゲートは、従来どおり両モデルへ優先適用します。

## v1.13 非重複ベースライン

モデル劣化判定を、直近7日とそれを含む30日集計の比較から、直近7日とその直前23日の完全に分離した比較へ変更します。直近データが基準側にも混ざって劣化幅が薄まる問題を防ぎます。

直近7日は最低10件、直前23日は最低20件を必要とします。どちらかが不足している間は`COLLECTING`とし、既存の全体安全ゲートを変更せず、SELL・PAPER MODE・`executionLocked: true`を維持します。

## v1.14 モデル復旧確認

モデル劣化の境界付近で成績が揺れたときにBUY停止と再開を繰り返さないよう、現在の直近7日対直前23日だけでなく、12時間前を基準にした同じ非重複窓も確認します。

現在窓が正常でも12時間前の確認窓に劣化が残る間は`RECOVERING`として、そのモデルだけ新規BUY停止を継続します。両方の窓が正常になった場合だけ`STABLE`へ戻します。SELL、他方の正常モデル、PAPER MODE、`executionLocked: true`は変更しません。

## v1.15 確信度スコア校正

チャートモデルとコミュニティトレンドの30日紙上結果を、確信度0–49・50–69・70–100の3帯に分け、件数・勝率・平均コスト後リターンを比較します。高確信度帯と70未満がそれぞれ10件に達するまで`COLLECTING`を維持します。

高確信度帯の損益がマイナスで、平均リターンも70未満を1ポイント以上下回る場合は`OVERCONFIDENT`として表示します。これはスコア設計の研究指標であり、既存のBUY・SELL判定やモデル劣化ゲートへ自動接続しません。

## v1.16 市場局面別の成績分解

チャートシグナルを保存するときに、その時点の市場局面（上昇・下降・レンジ・高ボラティリティ・低流動性）を記録します。30日紙上結果を局面別に分け、採点件数・勝率・コスト後平均リターン・Profit Factorを表示します。

過去レコードには市場局面が保存されていないため、v1.16以降の新しいシグナルから収集を開始します。各局面10件までは`COLLECTING`とし、この分析結果は戦略切替や売買ゲートへ自動接続しません。

## v1.17 局面別の成績悪化アラート

各市場局面で採点済み結果が10件に達した後、30日損益がマイナスで、平均コスト後リターンが-1%以下またはProfit Factorが0.80未満なら`PERFORMANCE ALERT`を表示します。10件未満は`COLLECTING`、警戒条件がない局面は`MONITORING`です。

アラートは研究用ダッシュボードの観測通知だけです。モデルの戦略切替、新規BUY停止、SELL、PAPER MODE、`executionLocked: true`を変更しません。

## v1.18 判断監査ビュー

新しい紙上シグナルへ最大5件の判断理由を保存し、直近の採点結果を判断ID単位で監査できるようにします。モデル、方向、スコア、確信度、エントリー価格、6時間後価格、想定コスト、コスト後損益、判断時刻を同じカードで確認できます。

既存レコードは判断理由なしのまま互換表示します。CSVにもスコア、確信度、市場局面、判断理由を追加しますが、秘密情報やウォレットアドレスは出力しません。監査情報は研究表示だけで、BUY／SELL判定には接続しません。

## v1.19 データ取得元の品質監視

Blockscout、Dexscreener、GeckoTerminal、Ethereum RPC、KyberSwapについて、今回スキャンの検査対象数・成功数・取得率・欠損率を同じ画面で表示します。Ethereum RPCは取得できた最新ブロックの最大データ年齢も表示します。

品質表示は読み取り専用です。対象なしを成功扱いせず`NO SAMPLE`、一部失敗を`PARTIAL`として可視化しますが、既存のFail Closed、SELL経路、PAPER MODE、`executionLocked: true`は変更しません。

## v1.20 24時間データ品質履歴

5分ごとの紙上スキャンへ各取得元の状態・取得率・データ年齢を保存し、直近24時間の可用率、平均取得率、現在の連続失敗数を表示します。旧レコードには品質情報がないため集計対象外とし、12回（約1時間）の観測までは`COLLECTING`です。

12回以降は可用率95%以上・平均取得率90%以上・連続失敗3回未満を`STABLE`、それ以外を`DEGRADED`として観測します。この履歴も研究用の読み取り表示だけで、BUY／SELL判定や既存の安全ゲートには接続しません。

## v1.21 取得元障害と復旧確認

取得元ごとに3回連続で`NO SAMPLE`になった時点を障害開始として記録し、直近24時間の障害回数・開始時刻・現在の失敗連続数を表示します。障害後は3回連続で`HEALTHY`を確認するまで復旧扱いにせず、途中の`PARTIAL`で復旧カウントをリセットします。

状態は`INCIDENT OPEN`、`RECOVERED`、`NO INCIDENT`、観測不足時の`WATCH COLLECTING`で表示します。障害監視は運用品質の可視化専用で、既存のFail Closed、SELL経路、PAPER MODE、`executionLocked: true`を変更しません。

## v1.22 判断時データ品質別の成績

6時間後に紙上判断を採点するとき、エントリー時点の5取得元を`COMPLETE`、`PARTIAL`、`UNAVAILABLE`へ分類し、平均取得率と不足元を結果へ紐付けます。品質記録のない旧データは`LEGACY / UNKNOWN`として推測せず分離します。

チャートモデルの30日成績を品質帯ごとに件数・勝率・コスト後損益・平均リターンで比較し、CSV監査にも同じ根拠を追加します。各帯10件までは`COLLECTING`とし、この分析はモデルや売買ゲートを自動変更しません。

## v1.23 取得元別の成績影響分析

Blockscout、Dexscreener、GeckoTerminal、Ethereum RPC、KyberSwapごとに、判断時にその取得元が正常だった結果と、`PARTIAL`または`NO SAMPLE`だった結果を分けて30日平均リターンを比較します。品質記録のない旧結果は比較から除外します。

正常時・品質低下時がそれぞれ10件に達し、品質低下時の損益がマイナスかつ平均リターン差が-1ポイント以下なら`PERFORMANCE ALERT`を表示します。これは原因候補を切り分ける研究アラートで、モデル切替、新規BUY停止、SELL、実行ロックを変更しません。

## v1.24 判断理由別の取得元影響分析

取得元ごとに、同じ判断理由が記録されたチャートモデル結果だけを正常時と品質低下時に分けて比較します。両群が各5件に達するまでは`COLLECTING`とし、条件を満たした理由のうち平均リターン差が最も悪いものを表示します。

品質低下時の損益がマイナスかつ平均リターン差が-1ポイント以下なら`REASON ALERT`を表示します。動的な判断文を根拠単位で監査する研究表示であり、モデル選択、BUY/SELLゲート、実行ロックには接続しません。

双方向見積はルートAPIの読み取り結果であり、実際のオンチェーン約定や売却成功を保証するものではありません。見積の有効時間は30秒として扱い、API停止時は安全側へ閉じて新規BUYを止めます。

バックテストとモンテカルロ再標本化は将来の利益や損失確率を保証しません。標準設定では片道ガス代を4ドル、スリッページを0.35%として保守的に判定します。約500ドル規模のEthereumメインネット運用では、チャートが良くてもコストゲートや耐久試験で注文を見送ることがあります。

## 実売買接続前の必須条件

1. ペーパートレードのシグナルと約定想定を最低7日・30件保存する
2. DEXの確定見積もりで価格影響・スリッページ・ガスを検査する
3. MetaMask Advanced Permissionsでスワップだけを許可する
4. 外部送金、借入、レバレッジ、未知コントラクトを拒否する
5. 永続的な緊急停止フラグと注文IDの重複防止をDBで実装する
6. 最初の実注文は1件ずつ人間が最終承認する

現在、1はデータ収集中、2・4・5は紙上モードで実装済みです。3と6は実売買接続を判断する将来段階まで意図的に未実装です。7日・30件を通過しても安全や利益は保証されず、自動的に実売買へ移行しません。

KyberSwap Aggregator APIのルート照会にはAPIキーを保存せず、公開エンドポイントへ`X-Client-Id`を付けてアクセスします。ルート情報からトランザクションやcalldataを生成せず、判定材料だけに使用します。

## セキュリティ方針

- 実行用秘密情報はクライアントへ渡さない
- 署名経路を追加するまでは、コード上も実資産を動かせない
- Vercel上ではBasic認証を必須化し、未設定時は失敗側へ閉じる
- ERC-20の無期限・無制限承認を使わない
